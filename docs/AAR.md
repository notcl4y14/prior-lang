# AAR

AAR (Abstract Assembly Represenation) - is tree-like structure similar to AST (Abstract Syntax Tree) generated by the AST parser. Its contents are made of AAR statements and expressions, together they represent the structure of the abstract assembly code. According to the compiler's algorithm, the generated AAR is later translated to actual assembly code that can be later assembled with the use of external tools (assemblers). Managing and optimizing the assembly code via the AAR is much simpler than textual assembly code. It was supposed to have multiple backends for assembly languages (NASM, GAS, etc.), but now I have to find the actual purpose of it if I'm only using GAS, like special nodes responsible for abstract representation of assembly operations that are not identical on different platforms and architectures, which could be useful.

Here is an example:

AAR:
```
LabelStatement:
  name: _main
MoveStatement:
  dst: (RegisterExpr: eax)
  src: (IntegerExpr: 12)
JumpStatement:
  label: L1
MoveStatement:
  dst: (RegisterExpr: eax)
  src: (IntegerExpr: 100)
LabelStatement:
  name: L1
MoveStatement:
  dst: (RegisterExpr: ebx)
  src: (IntegerExpr: 54)
AddStatement:
  dst: (RegisterExpr: eax)
  src: (RegisterExpr: ebx)
```

NASM code of the AAR:
```asm
_main:
  mov eax, 12
  jmp L1
  mov eax, 100
L1:
  mov ebx, 54
  add eax, ebx
```
